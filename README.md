# SmartDoc & Code Review v8

Веб-платформа для автоматической проверки Python-кода (PEP 8) и документов .docx (нормоконтроль ГОСТ/АГУ).

## Возможности

- Проверка .py на соответствие PEP 8 через flake8 (русские описания ошибок, дедупликация)
- Нормоконтроль .docx: шрифт, кегль, интервал, отступ, поля, подписи к рисункам/таблицам, список литературы
- Автоисправление .py (autoflake + autopep8, 3 прохода) и .docx (поля, шрифт, кегль, интервал, отступ, цвет, картинки)
- Пользовательские правила проверки .docx — пресет АГУ (ГОСТ) или свои значения (шрифт, кегль, поля, интервал)
- Подсветка ошибок прямо в исходном коде с minimap, тултипами и навигацией
- Вставка кода из буфера обмена (Ctrl+V) без создания файла
- Экспорт отчёта в PDF с фрагментами кода рядом с каждой ошибкой
- История проверок в браузере (localStorage, до 30 записей)
- Спокойный светлый интерфейс v8: одна страница, два состояния (загрузка → результат), drag-n-drop, адаптивная вёрстка

## Что нового в v8 — неразрушающее автоисправление

`docx_fixer.py` переписан по принципу «исправлять только отклонения»:

- текст, титульный лист, разделы, колонтитулы, разрывы страниц и закладки не трогаются;
- шрифт задаётся через стиль Normal, а не размазывается по всем run-ам;
- центрированные абзацы, элементы списков (нумерация Word), оглавление и подписи оформляются по своим правилам;
- 12 и 14 пт оба допустимы (эталон кафедры набран 12 пт), кегль не форсируется;
- удаляются только пустые абзацы между рисунком и подписью и повторные пустые строки в основном тексте — с защитой абзацев, несущих `sectPr`, `w:br`, рисунок или закладку.

Вердикт смягчён: одно критичное замечание — ещё «ok», два и больше — «bad».

Новый интерфейс: одна страница вместо «лендинг + инструмент». Пока файла нет — зона загрузки и иллюстрация листа А4 с замечаниями; после проверки та же область превращается в отчёт: список замечаний слева, вердикт и действия справа. Тёмная тема убрана.

Регрессия на эталоне кафедры (`tests/test_fixer_reference.py`): после autofix структура, текст и титульный лист совпадают с эталоном, число замечаний не растёт, повторный autofix ничего не меняет. Попутно убраны ложные срабатывания чекера: оглавление считалось заголовками (17 × HEADING_NOT_BOLD), списки и подписи к таблицам проверялись на красную строку, пустые строки титульника и разрывы страниц считались «лишними», «Продолжение таблицы» считалось новой таблицей, список литературы с нумерацией Word считался пустым, «формата .txt» считалось пробелом перед точкой. Эталон: 50 → 8 замечаний, после autofix — 2.

## Нормоконтроль .docx

Модуль проверяет документы по требованиям **АГУ им. В.Н. Татищева**, факультет цифровых технологий и кибербезопасности (ФЦТиК), направление 09.03.02. Инженерно-технический подход с ориентацией на ЕСКД.

Подробное описание требований: [`docs/Требования_нормоконтроля_АГУ_ФЦТиК.md`](docs/Требования_нормоконтроля_АГУ_ФЦТиК.md)

Проверяемые параметры: шрифт (Times New Roman, 14 пт), межстрочный интервал (1,5), отступ первой строки (1,25 см), поля страницы (3,5/1/2,5/2,5 см), выравнивание по ширине, заголовки (жирный, без точки), нумерация страниц, оглавление, подписи к рисункам/таблицам, список литературы, гиперссылки, цвет текста, пробелы, пустые строки, шрифт в таблицах.

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py
```

Откройте http://127.0.0.1:8000

## Деплой на Render.com

1. Загрузите проект на GitHub (создайте репозиторий и запушьте код)
2. Откройте [render.com](https://render.com) и зарегистрируйтесь
3. Нажмите **New → Web Service**
4. Подключите GitHub-репозиторий с проектом
5. Render автоматически определит настройки из `render.yaml`
6. Нажмите **Create Web Service**
7. Через 2–3 минуты сервис будет доступен по ссылке вида `https://smartdoc-xxxx.onrender.com`

Бесплатный тариф Render: сервис засыпает после 15 минут простоя. Первый запрос после сна может занять до 30 секунд.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/check` | Проверка (.py / .docx) → JSON-отчёт |
| POST | `/api/autofix` | Автоисправление → скачивание файла |
| POST | `/api/export-pdf` | Отчёт → PDF-файл |
| GET  | `/api/presets` | Список пресетов правил для .docx |
| GET  | `/health` | Health-check |

Эндпоинты `/api/check` и `/api/autofix` принимают необязательное поле `docx_rules` (JSON) для пользовательских правил проверки .docx.
