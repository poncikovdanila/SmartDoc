# SmartDoc & Code Review v8

Веб-платформа для автоматической проверки кода (Python, JavaScript, SQL, Java, C/C++) и документов .docx (нормоконтроль ГОСТ/АГУ).

## Возможности

- Проверка .py на соответствие PEP 8 через flake8 (русские описания ошибок, дедупликация)
- Проверка .js, .sql, .java, .cpp/.c/.h встроенными чекерами стиля — без Node.js и JDK
- Нормоконтроль .docx: шрифт, кегль, интервал, отступ, поля, подписи к рисункам/таблицам, список литературы
- Автоисправление .py (autoflake + autopep8, 3 прохода) и .docx (поля, шрифт, кегль, интервал, отступ, цвет, картинки)
- Пользовательские правила проверки .docx — пресет АГУ (ГОСТ) или свои значения (шрифт, кегль, поля, интервал)
- Подсветка ошибок прямо в исходном коде с minimap, тултипами и навигацией
- Вставка кода из буфера обмена (Ctrl+V) без создания файла
- Экспорт отчёта в PDF с фрагментами кода рядом с каждой ошибкой
- Пакетная проверка нескольких файлов за один запрос
- Предпросмотр автоисправления до скачивания: построчный diff для кода, сводка замечаний до/после для .docx
- История проверок в браузере (localStorage, до 30 записей)
- Спокойный светлый интерфейс v8: одна страница, два состояния (загрузка → результат), drag-n-drop, адаптивная вёрстка

## Что нового в v8 — многоязычная проверка и неразрушающее автоисправление

`docx_fixer.py` переписан по принципу «исправлять только отклонения»:

- текст, титульный лист, разделы, колонтитулы, разрывы страниц и закладки не трогаются;
- шрифт задаётся через стиль Normal, а не размазывается по всем run-ам;
- центрированные абзацы, элементы списков (нумерация Word), оглавление и подписи оформляются по своим правилам;
- 12 и 14 пт оба допустимы (эталон кафедры набран 12 пт), кегль не форсируется;
- удаляются только пустые абзацы между рисунком и подписью и повторные пустые строки в основном тексте — с защитой абзацев, несущих `sectPr`, `w:br`, рисунок или закладку.

Вердикт смягчён: одно критичное замечание — ещё «ok», два и больше — «bad».

Проверка кода перестала быть только питоновской: подключены чекеры JavaScript,
SQL, Java и C/C++ (раздел «Проверка кода» ниже). Интерфейс, экспорт в PDF и
история проверок работают для них так же, как для .py: подсветка исходника,
переход к строке, тот же формат отчёта и вердикта.

Новый интерфейс: одна страница вместо «лендинг + инструмент». Пока файла нет — зона загрузки и иллюстрация листа А4 с замечаниями; после проверки та же область превращается в отчёт: список замечаний слева, вердикт и действия справа. Тёмная тема убрана.

Регрессия на эталоне кафедры (`tests/test_fixer_reference.py`): после autofix структура, текст и титульный лист совпадают с эталоном, число замечаний не растёт, повторный autofix ничего не меняет. Попутно убраны ложные срабатывания чекера: оглавление считалось заголовками (17 × HEADING_NOT_BOLD), списки и подписи к таблицам проверялись на красную строку, пустые строки титульника и разрывы страниц считались «лишними», «Продолжение таблицы» считалось новой таблицей, список литературы с нумерацией Word считался пустым, «формата .txt» считалось пробелом перед точкой. Эталон: 50 → 8 замечаний, после autofix — 2.

## Проверка кода

| Расширение | Чем проверяется | Автоисправление |
|---|---|---|
| `.py` | flake8 (pycodestyle + pyflakes), лимит строки 79 | да, autoflake + autopep8 |
| `.js` | встроенный чекер: `var`, `==`, `eval`, `debugger`, `console`, именование | нет |
| `.sql` | встроенный чекер: регистр ключевых слов, `SELECT *`, `DELETE`/`UPDATE` без `WHERE` | нет |
| `.java` | встроенный чекер: PascalCase классов, camelCase методов, пустой `catch`, отладочный вывод | нет |
| `.cpp`, `.c`, `.h` | встроенный чекер: `using namespace std`, `goto`, `malloc`, `#include "<стандартный>"` | нет |

Встроенные чекеры выбраны вместо ESLint и checkstyle сознательно: те требуют
Node.js и JDK, а здесь достаточно `pip install -r requirements.txt`. Покрытия
хватает на типичные учебные ошибки — именование, отладочный мусор, небезопасные
конструкции.

Перед применением правил из строки вычищаются строковые литералы и комментарии
(`_mask_line`), поэтому `var` в комментарии или `SELECT *` внутри кавычек
замечанием не считаются. Длина строки при маскировании сохраняется, так что
номер колонки в отчёте указывает на настоящее место ошибки.

Автоисправление есть только для `.py` и `.docx`. Для остальных языков
`/api/autofix` отвечает 422 с понятным текстом, а кнопка в интерфейсе
выключена с подсказкой — молча ничего не происходит.

## Предпросмотр автоисправления

Кнопка «Что изменится?» рядом с «Исправить и скачать» показывает результат
до того, как файл изменён и скачан:

- для кода — построчный diff оригинала и результата с колонками «было» и
  «стало»; неизменённые участки длиннее шести строк сворачиваются, иначе
  diff по файлу на несколько сотен строк невозможно просмотреть глазами;
- для `.docx` — сколько замечаний снимет исправление, с разбивкой по
  критичности. Построчный diff тут невозможен: это архив с XML-разметкой,
  а не текст;
- если автоисправление ничего не изменит, окно так и говорит, а кнопку
  скачивания не показывает — бессмысленной загрузки не будет.

## Нормоконтроль .docx

Модуль проверяет документы по требованиям **АГУ им. В.Н. Татищева**, факультет цифровых технологий и кибербезопасности (ФЦТиК), направление 09.03.02. Инженерно-технический подход с ориентацией на ЕСКД.

Подробное описание требований: [`docs/Требования_нормоконтроля_АГУ_ФЦТиК.md`](docs/Требования_нормоконтроля_АГУ_ФЦТиК.md)

Проверяемые параметры: шрифт (Times New Roman, 14 пт), межстрочный интервал (1,5), отступ первой строки (1,25 см), поля страницы (3,5/1/2,5/2,5 см), выравнивание по ширине, заголовки (жирный, без точки), нумерация страниц, оглавление, подписи к рисункам/таблицам, список литературы, гиперссылки, цвет текста, пробелы, пустые строки, шрифт в таблицах.

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py
```

Откройте http://127.0.0.1:8000

## Деплой на Render.com

1. Загрузите проект на GitHub (создайте репозиторий и запушьте код)
2. Откройте [render.com](https://render.com) и зарегистрируйтесь
3. Нажмите **New → Web Service**
4. Подключите GitHub-репозиторий с проектом
5. Render автоматически определит настройки из `render.yaml`
6. Нажмите **Create Web Service**
7. Через 2–3 минуты сервис будет доступен по ссылке вида `https://smartdoc-xxxx.onrender.com`

Бесплатный тариф Render: сервис засыпает после 15 минут простоя. Первый запрос после сна может занять до 30 секунд.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/ -q   # 358 тестов
```

Линтер как в CI:

```bash
flake8 app/                                        # исходники приложения
flake8 --select=E9,F63,F7,F82 tests/ benchmark/    # только настоящие ошибки
```

На каждый push и pull request тесты и линтер прогоняются в GitHub Actions
(`.github/workflows/ci.yml`) на Python 3.11 и 3.12.

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/check` | Проверка одного файла (код или .docx) → JSON-отчёт |
| POST | `/api/check-batch` | Пакетная проверка нескольких файлов |
| POST | `/api/autofix` | Автоисправление → скачивание файла (.py и .docx) |
| POST | `/api/autofix-preview` | Предпросмотр результата автоисправления |
| POST | `/api/export-pdf` | Отчёт → PDF-файл |
| POST | `/api/generate-template` | Шаблон записки .docx по текущим правилам |
| GET  | `/api/presets` | Список пресетов правил для .docx |
| GET  | `/api/languages` | Поддерживаемые форматы и наличие автоисправления |
| GET  | `/health` | Health-check |

Эндпоинты `/api/check`, `/api/check-batch`, `/api/autofix` и
`/api/generate-template` принимают необязательное поле `docx_rules` (JSON)
для пользовательских правил проверки .docx.

Отчёт по коду и по документу имеет один формат: `filename`, `file_type`,
`total_issues`, `summary` (`high`/`medium`/`low`), `verdict`
(`good`/`ok`/`bad`), `issues`, `source_lines`. Благодаря этому фронтенд,
экспорт в PDF и история проверок работают одинаково для всех языков.
